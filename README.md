# 大学生竞赛信息与组队管理系统

软件工程课程项目，本机验收演示版 v0.2。沿用老师确认的三个板块、六个功能模块，按周、王、陈三个任务包分别补充代码、测试和文档。新增实现由AI辅助完成，个人责任分工不等于已经完成独立学习与个人过程材料。

## 立即演示

需要Python3.10+和现代浏览器，业务运行不需要第三方依赖。

双击 `start-acceptance.bat`，打开 <http://127.0.0.1:8000>。首次自动生成独立验收库 `data/acceptance.db`，含三支三人队伍及待审、驳回、通过三种报名；以后启动不清空。演示密码均为 `Demo123456`，账号 `zhou`、`wang`、`chen` 为学生，`admin` 为管理员。

```powershell
python tools/prepare_demo.py
python server.py --db data/acceptance.db --port 8000
```

上面的生成命令只在目标库尚不存在时运行，存在会拒绝覆盖。端口占用可改8001。原 `start.bat` 或 `python server.py` 仍打开原 `data/app.db`，没有重置原业务库。首次升级旧库会自动建立历史表：旧记录只生成诚实的现状迁移事件，不能恢复此前未记录的审核人和表单。

页面已使用自然的竞赛和队伍名称。报名状态在独立区域展示：“报名待审核”表示已提交等待管理员处理；“需要修改报名”表示队长需按修改原因调整并在截止前重提；“报名已通过”表示审核完成。底层仍使用 `pending / rejected / approved`，入队申请使用独立的状态文案。

已有库的旧初始化文案可定向整理，默认预览，应用前自动备份；重复执行不会再次修改。不会清库或替换用户自行填写的相似文本。操作范围、来源说明和验证记录见 [初始化文案整理](docs/初始化文案整理.md)。


## 业务规则

学生和管理员是账号角色，队长是队伍创建者。每人同竞赛最多属于一队，队长计入人数；批准入队前再次检查容量与归属，并在统一写事务中提交。首次报名后队伍资料与成员锁定，驳回也不解锁。报名仅有待审核、通过、驳回，驳回须说明且只能截止前重提；管理员可审核已截止前提交的记录。

下架或截止禁止建队、申请、批准和提交；允许未报名成员退出、移除与撤回意愿。下架队伍对成员、本人有待审申请的学生和管理员可见，以保留撤回入口。已有任何报名的竞赛锁定上下限和截止时间，名称简介等仍可修改。日期型截止包括当日，精确时间按时区比较。名单与操作者姓名保存快照，个人资料变化不改写历史；队伍及竞赛标题仍显示当前值。

联系人、参赛说明和历史仅本队成员与管理员可见；CSV复用相同授权并处理公式前缀。公开资料包括姓名、专业、年级、技能简介，注册/资料页面已说明用途。内置竞赛与号码仅用于演示，系统报名不自动同步外部官网。

## 验证

```powershell
python tools/verify.py
```

保存 `output/acceptance/test-results.json`、`tests.log`、`performance.json`。也可运行 `python -m unittest discover -s tests -v`。测试仅用tmp/独立库和随机端口，不改业务数据。当前29组后端与迁移测试，覆盖完整流程、角色、输入、日期、并发、快照、迁移、导出、持久性和初始化文案整理；具体最新执行结论以JSON为准，不代表代码覆盖率。

可选页面验证脚本 `tools/browser_check.cjs` 需要Playwright及Edge，对BASE_URL指定的独立测试库操作并保存截图和 `browser-results.json`。统计脚本 `python tools/project_metrics.py` 只统计物理行数与真实仓库提交，不推算个人贡献和AI比例。

## 数据备份与部署范围

```powershell
python tools/backup_data.py --db data/acceptance.db
python tools/prepare_demo.py --db data/acceptance-2.db
```

SQLite backup API做一致性备份，目标存在不覆盖。生成新库不清理旧库。Git不包含数据库，克隆后使用验收启动脚本生成即可。演示数据截止为生成后60天，过期请新建演示库。

服务仅监听127.0.0.1，密码带盐PBKDF2哈希，Cookie为HttpOnly和SameSite=Strict；会话保存在内存，服务重启需重新登录。此版本面向课堂本机演示；尚无TLS、互联网部署配置、登录限流、学校统一认证和大规模负载验证。

历史进度保留在《开发进度与明日演示.md》，仅反映2026-10-20，不作为v0.2的当前完成清单。
