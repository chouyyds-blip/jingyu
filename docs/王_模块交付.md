# 王负责的队伍管理与招募申请模块

更新日期：2026-11-03。本文把原有三人分工中的王任务包落实为两个功能模块，作为代码交接、个人复核和课堂验收依据。代码和测试由 AI 辅助完善；责任归属表示后续学习与维护边界，不能证明王本人已经独立完成课程要求的全部活动。

## 一 个人贡献边界

王负责队伍创建、信息维护、解散、成员退出与移除，以及招募展示、入队申请、撤回和队长审批。实现位于 `modules/teams.py`，新增测试位于 `tests/test_wang.py`。不负责账号密码、竞赛发布、正式报名与管理员审核。前端共用 `static/app.js`，公共事务和身份上下文由 `server.py` 提供。

## 三 设计与接口

模块通过 `handle(ctx, method, path, data)` 接收 HTTP 层路由。私有函数隐藏竞赛开放规则、队长权限、报名锁定、同竞赛归属和人数查询细节。数据库写入统一由 HTTP 层 `BEGIN IMMEDIATE` 事务提交，因此两个审批请求无法同时依据同一旧人数写入；发生校验错误时，当前请求回滚。

| 方法与路径 | 输入 | 权限及规则 | 结果 |
| --- | --- | --- | --- |
| GET /api/teams | 可选 competition_id 查询参数 | 访客可浏览上架竞赛队伍；下架队伍仅本队成员、本人持有待审申请者和管理员可见；撤回或离队后不再满足可见条件即隐藏 | 队伍、人数、成员、本人申请；队长额外获得本队申请 |
| POST /api/teams | competition_id、name、intro、requirements | 学生；竞赛开放；本人尚无同竞赛队伍 | 创建队伍并加入创建者；同竞赛其他待审申请自动拒绝 |
| PUT /api/teams/{id} | name、intro、requirements | 队长；从未提交报名 | 更新队伍资料 |
| DELETE /api/teams/{id} | 无 | 队长；从未提交报名；界面应二次确认 | 删除队伍及其成员关联和申请 |
| DELETE /api/teams/{id}/members/me | 无 | 本队非队长成员；从未提交报名 | 本人离队，原批准申请改为 rejected，之后可重新申请 |
| DELETE /api/teams/{id}/members/{uid} | 无 | 队长；目标为非队长成员；从未提交报名；界面应二次确认 | 移除成员，原批准申请改为 rejected |
| POST /api/teams/{id}/apply | message | 学生；竞赛开放、队伍未报名且未满、本人无同竞赛队伍 | 新建待审申请；被拒申请可复用编号重新提交 |
| DELETE /api/applications/{id} | 无 | 仅申请者本人，状态必须 pending | 删除待审申请；再次申请重新创建记录 |
| POST /api/applications/{id}/review | status 为 approved 或 rejected | 本队队长；队伍未报名；只能处理 pending；批准时检查开放和人数 | 保存结果；批准时加入成员并拒绝其同竞赛其他待审申请 |

名字最多 50 字，队伍介绍最多 1000 字，招募要求与申请说明最多 500 字；编号必须是正整数。错误响应使用项目现有规范：未登录为 403，其他输入和业务权限错误为 400。这里保留现有规范，避免仅本模块改变 HTTP 状态码导致界面与既有测试不一致。

截止和下架禁止新增队伍、申请及批准入队，但允许未报名队伍的退出、移除、解散及待审申请撤回，以便清理意愿和成员关系。上述清理不绕过报名后的名单锁定。撤回待审申请不改变成员名单，因此即使队伍已报名，也可撤回仍未处理的申请。

本次不增加“撤回”数据库状态：撤回采用删除待审申请的最小方案；退出/移除把旧 approved 记录改为 rejected，让现有重新申请规则继续复用。代价是申请表不构成完整审计日志，不能用它还原每次历史申请或离队原因；若未来需要审计，应单独设计事件表，不应把 rejected 解读成只有队长拒绝这一种原因。

## 四 核心过程

建队流程：身份验证 → 学生角色 → 竞赛开放 → 同竞赛无队伍 → 校验字段 → 写队伍 → 加入队长 → 拒绝其他待审申请 → 同事务提交。

审批流程：登录 → 读取申请和队伍 → 队长权限 → 未报名 → 待审状态 → 如批准则重新校验竞赛开放、归属和人数 → 添加成员 → 拒绝其他申请 → 保存审批状态 → 同事务提交。

离队流程：登录 → 读取队伍 → 如移除则检查队长身份 → 禁止目标为队长 → 未报名 → 校验目标成员确实存在 → 删除成员关联 → 将旧批准申请改为 rejected → 同事务提交。

## 五 测试设计与执行

执行命令：`python -m unittest discover -s tests -p test_wang.py -v`。测试通过真实本机 HTTP 请求运行，使用独立测试数据库，不修改 `data/app.db`。

| 测试方法 | 正常与异常覆盖 |
| --- | --- |
| test_member_leave_remove_and_reapply | 加入后退出、重申、被队长移除及再次申请；人数正确减少 |
| test_member_permissions_and_registration_lock | 访客、非队长、非成员及队长自退限制；报名后退出和移除均失败 |
| test_withdraw_own_pending_only_and_reapply | 本人撤回后可重申；他人、访客和已批准申请不能撤回 |
| test_closed_competition_allows_cleanup_but_no_new_members | 下架截止后待审本人仍可找到队伍并撤回，撤回或离队后隐藏；访客及无关学生不可见；禁止批准及新申请 |
| test_create_team_rejects_other_pending_applications | 学生申请其他队伍后自行建队，旧申请自动拒绝 |
| test_concurrent_approval_has_one_capacity_winner | 两人同时争取最后一个名额，只能一人批准，人数不超限 |
