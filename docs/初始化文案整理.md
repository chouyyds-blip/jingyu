# 初始化文案整理（2026-11-03）

本次由AI辅助修改代码、生成验证和执行数据库定向整理，仍沿用周负责用户与竞赛、王负责队伍与招募、陈负责报名与审核的边界。此前工程文档中的数据来源、课程背景和AI贡献说明保留；没有把内置名称改写成已核验的真实官方赛事。

## 页面行为

竞赛、队伍标题只展示名称。新建验收库和既有验收库统一使用校园应用开发挑战赛／星火开发队、校园服务创新赛／青禾创作队、校园软件实践赛／远航实践队等通用校园名称。这些名称由项目设定，不代表已核验的官方竞赛；没有添加虚构主办方、官方链接或报名同步能力。

| 存储状态 | 页面与报名CSV | 含义 |
| --- | --- | --- |
| pending | 报名待审核 | 已提交报名，等待管理员处理。 |
| rejected | 需要修改报名 | 管理员指出问题，队长按修改原因调整，在截止前重新提交。 |
| approved | 报名已通过 | 报名审核已完成。 |

状态说明在报名页和各记录的独立区域展示；需要修改的记录显示具体原因，重新打开表单仍可见原因。管理员操作改称“要求修改”，历史事件仍保留原动作码。入队申请的状态不套用报名说明。报名状态机、审核权限、成员锁定和截止限制保持原逻辑。

产品侧栏、页头、页脚、登录与联系人提示，以及初始化名称、简介、申请留言、参赛说明和固定审核意见中的测试环境字样已整理。账号和原密码保留，登录快捷入口称为“初始账号”。

## 定向迁移与备份

`tools/migrate_seed_content.py` 默认只预览；加 `--apply` 才写入。可重复使用 `--db` 指定数据库；默认检查现有 `data/app.db` 和 `data/acceptance.db`。源库不存在时不创建空库。

只匹配已知编号、完整旧名称与简介、分类、人数、空官网链接等来源指纹。队伍还核对队长身份、固定介绍与招募要求、成员归属；原业务库的实践队另核对原创建时间。下级字段逐项匹配固定原值，不做全库字符串替换。用户自写内容和不满足指纹的记录保留，由人工另行判断。

写锁覆盖指纹检查、SQLite一致性备份和更新。备份通过完整性检查后才更新源库；更新后检查完整性与外键，失败回滚。幂等执行无待更新字段时不额外创建备份。

原业务库尚无报名历史表；本次迁移不补造旧审核历史。正常启动时仍由原初始化机制记录可证实的迁入现状，原审核人未知。
