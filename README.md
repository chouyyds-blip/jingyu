# 大学生竞赛信息与组队管理系统

软件工程课程实践项目，开发初版 v0.1。按周、王、陈的拟定分工组织代码，保留三个业务板块、六个功能模块。

## 启动

需要 Python 3.10 或以上版本，无需安装第三方依赖。在项目目录双击 `start.bat`，或者在终端运行：

```powershell
python server.py
```

保持终端窗口打开，使用浏览器访问 <http://127.0.0.1:8000>。首次启动自动创建 SQLite 数据库及演示账号。如果 8000 端口被占用，可以运行 `python server.py --port 8001`，然后访问相应地址。

## 主要业务规则

- 学生与管理员是两种账号角色；队长是队伍创建者。
- 一个学生在同一竞赛最多属于一支队伍；队长计入总人数。
- 队伍满员不能继续申请或批准新成员；加入一队后，同一竞赛的其他待审申请自动拒绝。
- 下架或截止的竞赛不能新建队伍、申请加入或提交报名。
- 只有队长能处理本队申请、修改本队信息及提交报名；管理员负责竞赛维护和报名审核。
- 首次提交报名后，队伍资料和成员锁定，包括驳回状态，以保持报名名单一致。
- 报名只有待审核、已通过、已驳回三种状态；驳回须填写原因，截止前可修改后重新提交。
- 联系电话及报名内容仅管理员和本队成员可查看。
- 日期型截止时间（如 `2026-12-19`）包括当天；界面默认采用精确到分钟的本机时间。

## 演示流程

本机交付时的演示库已经保存一条完整结果：“周王陈 · 课程实践队”包含周、王、陈，参加“校园软件创意设计赛（演示）”，报名已通过。可以直接展示队伍及报名记录。`13800000000` 是演示用号码，不是真实联系方式。

GitHub 仓库不包含本地数据库。通过 Git 克隆后首次启动只会自动生成演示账号和三项演示竞赛，队伍及报名记录需按下面的流程创建。

若要从头操作，请使用另一项竞赛，例如“大学生数据应用挑战赛（演示）”，或者让管理员新建一项竞赛。下面以新的一轮操作为例：

1. 周登录，在“发现竞赛”选择一项尚未加入队伍的演示竞赛，查看详情并创建新队伍。
2. 退出后用王登录，在“队伍与招募”找到该队，提交入队申请。
3. 用陈登录，重复提交申请。
4. 用周登录，打开新队伍详情，同意王、陈的申请，成员达到 3 人。
5. 周点击“提交报名”，填写联系人、演示电话（例如 `13800000000`）和参赛说明，提交后状态为待审核。
6. 管理员登录，在“报名记录”通过或驳回报名。
7. 切回周或其他队员，查看审核状态。若驳回，周可修改后重提。

管理员没有学生组队资格，演示时请注意切换账号。已通过的记录不会自动重置，若需要重复演示，可以由管理员新建另一项演示竞赛，再重新开始。

## 测试

```powershell
python -m unittest discover -s tests -v
```

测试使用 `tmp/` 内独立临时数据库和随机本地端口，不改变 `data/app.db`。已验证 4 组 HTTP 集成测试：账号与权限、完整组队报名流程、截止/满员/下架限制、输入及跨站请求校验。其中包含重复申请、非队长审批、报名人数不足、重复报名、驳回重提及报名隐私检查。

## 数据与范围

SQLite 文件在 `data/app.db`，这是后续操作的实际保存位置。复制项目到其他机器时，如需保留演示记录，应一并保留该文件。密码以带盐 PBKDF2 哈希保存，登录通过 HttpOnly Cookie 维护，会话在内存中。

内置竞赛均明确标为演示数据，官方链接默认留空。报名是本系统内的登记和审核，不自动同步到外部竞赛官网。

本阶段不包含：智能匹配、聊天、消息推送、附件上传、成果档案、统计分析、学校统一认证。后续重点是补充课程要求的需求文档、架构设计、测试记录及操作体验，不继续扩充板块。
