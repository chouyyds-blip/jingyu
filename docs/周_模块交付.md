## 需求与边界

| 需求 ID | 模块 | 需求及验收标准 | 来源与状态 |
| --- | --- | --- | --- |
| FR-U01 | 用户与权限 | 注册账号只能为学生；登录返回公开资料，不返回密码哈希；未登录不能修改资料，学生不能发布或修改竞赛；退出后原会话失效 | 既有范围，AI 辅助实现，个人审定待完成 |
| FR-U02 | 用户与权限 | 登录用户输入正确原密码后可设置 8 至 128 位的新密码；禁止与原密码相同；改密成功后当前会话保留，同账号其他会话失效；旧密码不能再登录 | 本次 AI 建议与实现，个人采纳决定待完成 |
| FR-C01 | 竞赛信息 | 访客浏览上架竞赛，支持关键词和精确分类组合查询；分类最长 30 字；管理员可查看下架竞赛，维护标题、简介、截止时间、人数与官网链接 | 既有范围，分类组合查询本次补齐 |
| FR-C02 | 竞赛信息 | 最多人数不得低于任何既有队伍人数；组队未完成时可提高最低人数；一旦出现任何状态的报名，人数上下限及截止时间锁定，名称、简介和上架状态仍可修改 | 本次完整性修复，个人审定待完成 |

用户模块负责身份和权限，不负责队伍成员变更与报名审核。竞赛模块负责竞赛基础规则，不代替王的队伍管理和陈的报名管理。管理员不通过公开注册产生。演示账号与密码仅用于本机课程环境。

## 输入输出与接口

| 接口 | 输入 | 权限 | 输出与异常 |
| --- | --- | --- | --- |
| POST /api/register | username、password、name | 访客 | 返回学生公开资料并建立会话；重复用户名或无效字段返回 400 |
| POST /api/login | username、password | 访客 | 正确时返回公开资料和 HttpOnly 会话 cookie；错误返回 400 |
| POST /api/logout | 空对象 | 当前会话 | 清除当前会话与 cookie |
| GET /api/me | 无 | 所有人 | 返回当前公开资料或 null |
| PUT /api/profile | name、major、grade、skills | 已登录 | 保存允许修改的字段，忽略 role 等提权字段 |
| PUT /api/password | old_password、new_password | 已登录 | 原密码正确且新密码合法则保存新哈希，撤销其他会话；未登录 403，输入错误 400 |
| GET /api/competitions | 查询参数 q、category | 所有人 | 返回筛选后的竞赛数组；普通用户仅见上架记录 |
| POST /api/competitions | 完整竞赛资料 | 管理员 | 新建记录；人数范围需满足 1 ≤ 最少 ≤ 最多 ≤ 20 |
| GET /api/competitions/{id} | 路径编号 | 所有人 | 普通用户仅能查询上架记录 |
| PUT /api/competitions/{id} | 需要修改的竞赛字段 | 管理员 | 校验合并后的全部字段和既有业务约束，失败时整次修改回滚 |

密码使用带随机盐的 PBKDF2-SHA256，比较使用恒定时间比较函数。业务模块调用 Context 的会话撤销接口，不直接访问 HTTP 服务器的会话字典。这一依赖方向把身份业务和会话存储细节分开。

## 设计与关键易变点

用户与竞赛业务均位于 `modules/users.py`；公共 HTTP 入口负责 JSON、事务、cookie 和错误码。竞赛更新先合并旧数据与输入，再执行字段验证和关联检查，最后执行单条更新；HTTP 层使用写事务，使读到的队伍人数与后续竞赛更新保持一致。

关键易变点是密码策略和会话期限、竞赛人数规则、报名后的规则变更政策。现阶段采用“已有报名后锁定资格字段”，以避免回溯修改导致已登记报名失效。若后续需要延期，应单独评估延期通知、重新开放流程和历史规则快照，不直接移除此保护。

## 自动化验收

运行 `python -m unittest discover -s tests -p test_zhou.py -v`。测试继承公共 HTTP 测试夹具，创建独立数据库与本地随机端口，不更改演示库。

| 用例方法 | 核心断言 | 关联需求 |
| --- | --- | --- |
| test_password_change_revokes_other_sessions | 验证原密码、短密码、相同密码和异常类型；合法改密后保留当前会话并撤销其他会话，验证新旧密码登录结果 | FR-U01、FR-U02 |
| test_competition_rules_protect_existing_teams | 两人队伍允许提高最低人数继续招募，禁止将最多人数降为一人；错误请求不改变旧规则 | FR-C02 |
| test_registration_freezes_eligibility_rules | 提交报名后禁止变更上下限和截止时间，允许修改名称和下架，已有报名仍可查询 | FR-C02 |
| test_category_and_query_filters_compose | 关键词和分类组合只返回目标竞赛，超长分类被拒绝，SQL 语句样式输入不扩大结果 | FR-C01 |

已有 `tests/test_system.py` 还验证注册、角色防提权、登录退出和管理员维护权限。执行结果以本次真实测试日志和最终总体验证报告为准，本文不预填通过数或覆盖率。
